3. 如何补充真实 FASTQ→counts 流程

真实流程要补的是 rnaseq-mvp-longread 背后的执行器。建议第一版先做 ONT FASTQ 到 gene-level counts。

3.1 第一版目标

ONT FASTQ
→ minimap2 splice-aware alignment
→ samtools sort/index
→ featureCounts gene assignment
→ gene_counts_raw.tsv
→ alignment_summary.tsv
→ longread_qc_metrics.tsv
→ provenance.json
→ validation_report.json

3.2 服务器依赖

建议用 Docker/Apptainer 容器固定工具版本，避免服务器环境漂移。若先用系统包试跑，可安装：

apt-get update
apt-get install -y minimap2 samtools subread seqkit
工具 用途
minimap2长读长 RNA-seq 到基因组的 splice-aware 比对。
samtoolsBAM 排序、索引、统计。
featureCounts按 GENCODE GTF 做 gene-level read assignment。
seqkitFASTQ reads 数量、长度、N50 等基础 QC。

4. 推荐开发方案

阶段 A：新增 long-read CLI 命令入口

在 src/rnaseq_mvp/cli.py 中新增命令，例如：

rnaseq-mvp longread-run \
  --samplesheet /root/heng-rna/runtime/runs/LR_TEST/longread_samplesheet.csv \
  --fasta /root/heng-rna/runtime/reference/human_grch38_gencode_v50_primary/GRCh38.primary_assembly.genome.fa.gz \
  --gtf /root/heng-rna/runtime/reference/human_grch38_gencode_v50_primary/gencode.v50.primary_assembly.annotation.gtf.gz \
  --outdir /root/heng-rna/runtime/results/longread/LR_TEST

也可以保留当前占位命令名 rnaseq-mvp-longread，但更推荐集成到 Typer CLI，方便测试和部署。

阶段 B：实现命令构建函数

新增一个确定性函数，例如：

build_minimap2_command(sample, fastq, fasta, sam_path)
build_samtools_sort_command(sam_path, bam_path)
build_featurecounts_command(bam_paths, gtf, counts_path)

不要一开始就把所有逻辑写成一大段 shell。每个命令单独生成、单独测试。

阶段 C：执行流程

# 1. 比对
minimap2 -ax splice -uf -k14 reference.fa sample.fastq.gz > sample.sam

# 2. 排序
samtools sort -@ 8 -o sample.sorted.bam sample.sam

# 3. 索引
samtools index sample.sorted.bam

# 4. BAM 统计
samtools flagstat sample.sorted.bam > sample.flagstat.txt

# 5. gene-level counts
featureCounts \
  -T 8 \
  -L \
  -t exon \
  -g gene_id \
  -a annotation.gtf \
  -o featurecounts.gene_counts.txt \
  sample.sorted.bam
注意：minimap2 -uf -k14 更适合 ONT direct RNA。对于 ONT cDNA，可能使用 -ax splice 即可。第一版需要根据 protocol 分别选择参数。

阶段 D：featureCounts 输出规范化

featureCounts 默认输出不是最终治理 counts，需要转换为：

gene_id	gene_name	SAMPLE_001
ENSG00000000003.18	TSPAN6	12
ENSG00000000419.16	DPM1	301

建议新增函数：

normalize_featurecounts_gene_counts(
    featurecounts_output,
    gtf_path,
    sample_id,
    output_path
)

该函数负责：

  • 读取 featureCounts 结果；
  • 提取 Geneid 和 count；
  • 从 GTF 建立 gene_id → gene_name 映射；
  • 输出标准 gene_counts_raw.tsv。

阶段 E：QC 文件生成

生成两个标准 QC 文件：

longread/alignment_summary.tsv
longread/longread_qc_metrics.tsv

第一版建议包含：

metric 来源 第一版处理
total_readsseqkit stats必需
total_basesseqkit stats必需
read_n50seqkit stats缺失则 WARN
alignment_ratesamtools flagstat必需
gene_assignment_ratefeatureCounts summary必需

阶段 F：provenance

每次运行必须记录：

{
  "method_profile_id": "longread_rnaseq_minimap2_gene_counts_v1",
  "measure_type": "assigned_longread_gene_counts",
  "aligner": "minimap2",
  "quantifier": "featureCounts",
  "reference_profile_id": "human_grch38_gencode_v50_primary",
  "samplesheet_sha256": "...",
  "commands": [...]
}

6. 推荐实施顺序

  1. 先把当前本地代码提交并部署到服务器。
  2. 服务器确认 long-read 骨架文件存在，测试通过。
  3. 本地继续开发 rnaseq-mvp longread-run 命令。
  4. 用 tiny FASTQ/FASTA/GTF 完成单元测试和集成测试。
  5. 服务器安装或容器化 minimap2/samtools/subread/seqkit。
  6. 服务器跑 smoke test。
  7. 再选择一个小型真实 ONT public FASTQ 做真实验证。
  8. 最后再考虑接入 GEO/SRA 公共目录和用户上传流程。

7. 不建议现在做的事

  • 不要直接用完整公共 long-read 数据集做首次测试。
  • 不要把 long-read counts 和 short-read Salmon counts 直接合并做差异分析。
  • 不要同时支持 ONT、PacBio、isoform discovery、modification calling。
  • 不要让 LLM 判断 QC 是否通过，必须由确定性指标和阈值判断。
